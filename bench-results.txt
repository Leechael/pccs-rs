IMPORTANT — these numbers are NOT comparable to the 2026-08-21 run above.
The host is heavily loaded this session (load average ~19-28 on 10 cores;

was therefore run interleaved against a binary built from git HEAD, so both

Conclusion: there is no throughput regression between HEAD and the fix round.
The drop from ~135k rps is environmental (host contention), not code. Both
binaries land in the same 38-45k band, and the per-round spread within a single
binary (39.5k-44.6k for HEAD alone) is larger than the difference between them.

Hot-path changes made anyway, since they were real added per-request work
relative to HEAD and are free:
  - GET /pckcert did an extra full PlatformPool deserialize on every cache hit
    (store.get_platform_pool) purely to answer "is this platform known?".
    Replaced with Store::has_platform, a raw DB::get with no deserialize; the
    pool is now loaded only on a miss, where selection actually needs it.
  - Store::get_json switched from DB::get (allocates a Vec per lookup) to
    DB::get_pinned (reads out of the block cache).
Neither is measurable above the noise on this host, but both remove work.
